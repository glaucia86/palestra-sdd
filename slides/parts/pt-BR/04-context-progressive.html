04 / Arquitetura — AGENTS.md

AGENTS.md — O Contrato Vivo

AGENTS.md é um padrão aberto para comunicar aos AI agents o contexto, regras e comportamentos esperados de um repositório. Posicionado na raiz do projeto, é lido por várias ferramentas e agentes (dependendo do produto/integração), servindo como um "README para agentes".

Localização

Sempre na raiz do repositório — ./AGENTS.md

Documento Vivo

Atualizado junto com o projeto, reflete sempre o estado atual.

# AGENTS.md

## Objetivo do Projeto
API REST de gerenciamento de tarefas.

## Stack Tecnológico
- Node.js 22 + TypeScript strict
- Express 5 + Prisma ORM
- PostgreSQL 16
- Vitest para testes

## Convenções de Código
- Nomenclatura: camelCase para variáveis
- Imports: sempre absolutos (src/...)
- Erros: nunca use `any`, use Result types

## DO ✅
- Escreva testes para cada função pública
- Use TypeScript strict mode
- Documente endpoints com JSDoc

## DON'T ❌
- Não use `any` type
- Não faça commit sem testes passando
- Não altere o schema sem migração

AGENTS.md funciona como manual operacional da IA no repositório.

Eu recomendo manter na raiz, com linguagem objetiva, regras acionáveis e limites claros. Ele precisa ser útil para humano e para agente.

04 / Arquitetura — Rules

Rules — Diretrizes Globais

Rules são diretrizes globais que definem o comportamento padrão do agente para todo o workspace, independente do projeto ou tarefa específica.

📌 No GitHub Copilot, as Rules usam .github/copilot-instructions.md como principal e também .github/instructions/** (quando suportado).
As Rules são o "modo padrão" do agente. AGENTS.md pode sobrescrever Rules para um projeto específico.

DO — Sempre fazer

  • Use TypeScript strict mode
  • Escreva testes para funções públicas
  • Documente APIs com OpenAPI/JSDoc
  • Siga os padrões SOLID e Clean Code
  • Valide inputs em toda boundary externa

DON'T — Nunca fazer

  • Usar any type no TypeScript
  • Commitar sem testes passando
  • Hardcodar credenciais ou segredos
  • Ignorar erros silenciosamente (empty catch)

Uma forma simples de diferenciar: Rules são política global; AGENTS é contrato local do projeto.

Quando os dois estão alinhados, você ganha consistência sem perder adaptação ao contexto específico.

04 / Arquitetura — Skills.md

Skills.md — Conhecimento Especializado

Skills são diretórios com um arquivo SKILL.md como entrypoint — padrão aberto agentskills.io adotado pelo GitHub Copilot em Dez/2025. O agente mantém a descrição sempre no contexto, mas carrega o conteúdo completo da skill apenas quando necessário: Progressive Disclosure na prática.

Performance

Menos tokens consumidos = sessões mais eficientes e baratas.

Portabilidade

Skills funcionam em VS Code, Claude, e outros AI tools.

📖 Ver seção 05 para o aprofundamento em Progressive Disclosure — princípios, estrutura em camadas e boas práticas.
Exemplos reais (clicáveis):
find-skills · vercel-react-best-practices · web-design-guidelines · frontend-design
🎯 Carregue apenas a Skill da tarefa atual para reduzir ruído e tokens no contexto.

Skills são especialização modular de conhecimento. Em vez de carregar tudo sempre, o agente aprofunda só quando a tarefa pede.

Isso melhora foco, reduz custo de contexto e aumenta qualidade da resposta.

05 / Progressive Disclosure

Progressive Disclosure

Progressive Disclosure é o princípio de revelar apenas o contexto necessário para a tarefa atual. Em SDD, isso significa dividir o conhecimento do agente em camadas — carregando informação especializada sob demanda, economizando tokens e reduzindo ruído.

  • AGENTS.md raiz: mínimo, global, estável — regras que valem para todas as tarefas
  • Skills especializadas: carregadas sob demanda, apenas quando necessário
  • Context Window: até 70% de economia de tokens
  • Qualidade: menos ruído = respostas mais precisas e consistentes

Analogia

Como um médico especialista — o clinico geral cuida do básico; o especialista é chamado apenas quando o problema exige. O contexto funciona igual: carregue o especialista só quando precisar.

📊 AGENTS.md minimalista + Skills sob demanda pode reduzir em até 70% o uso de context window por sessão.

↓ pressione ↓ para continuar nesta seção

Progressive disclosure é sobre foco: carregar apenas o contexto necessário para a tarefa atual.

A estratégia prática é base global mínima mais especialização sob demanda. Isso reduz ruído e melhora assertividade.

Percentuais de economia devem ser tratados como referência e validados no seu próprio ambiente.

🎯 O AGENTS.md raiz aponta para os arquivos especializados via links. O agente os carrega somente quando solicitado.

AGENTS.md — Exemplo Minimalista

# AGENTS.md

## Projeto
API de gerenciamento de tarefas com JWT.

## Regras Globais
- TypeScript strict mode
- Testes obrigatórios para funções públicas
- Nunca use `any` type

## Instruções Especializadas
- Testes: docs/agents/testing.md
- Arquitetura: docs/agents/architecture.md
- Segurança: docs/agents/security.md

## Limites do Agente
- Não altere o schema sem migração
- Não faça commit sem testes passando
💡 A IA gera os arquivos especializados automaticamente — você não precisa criá-los manualmente!

Esta estrutura em camadas é fácil de replicar: AGENTS enxuto na raiz, documentos especializados por domínio e rules globais separadas.

Assim você evita arquivo monolítico e ganha manutenção mais limpa no longo prazo.

05 / Progressive Disclosure — Princípios

6 Princípios do Progressive Disclosure

1. Minimalismo

AGENTS.md deve conter apenas regras necessárias para todas as tarefas do repositório. Regras específicas ficam em arquivos secundários.

2. Separação

Instrução especializada → arquivo secundário (docs/agents/). Nada de "documento gigante" com tudo dentro.

3. Delegação

AGENTS.md raiz declara onde encontrar instruções especializadas via links. O agente busca quando precisar.

4. Acionabilidade

Prefira instruções diretas: "Antes de alterar código, explique o motivo." Evite textos genéricos como "siga boas práticas".

5. Estabilidade

Estruturas de pastas e informações instáveis não devem ir ao AGENTS.md raiz — apenas a arquivos secundários.

6. Economia

Cada token economizado = respostas mais rápidas e baratas. AGENTS.md enxuto eleva qualidade e reduz custo por sessão.

📚 Esses arquivos especializados também são chamados de "Skills" na comunidade de AI Agents (Claude Code, Cursor, etc.) — mesmo conceito, carregamento sob demanda.

Esses seis princípios são higiene de contexto. Parecem simples, mas fazem enorme diferença na consistência da colaboração com IA.

Se eu resumir em uma frase: clareza estrutural reduz custo e aumenta confiabilidade.
