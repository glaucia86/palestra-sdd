PRD.md, AGENTS.md, Rules e Skills — os quatro pilares do contexto estruturado

Agora chegamos ao ponto mais estrutural da palestra — e possivelmente o com maior impacto prático no dia a dia do time: como organizar artefatos de contexto para que o agente trabalhe de forma consistente.

A pergunta prática que esse bloco responde: por que duas sessões com o mesmo agente, mesmo modelo e mesma tarefa produzem resultados tão diferentes? Geralmente a resposta está na qualidade do contexto de entrada, não na escolha do modelo.

Leiam este diagrama como pipeline de engenharia: entradas bem definidas produzem saídas consistentes. A qualidade da saída — código, testes, documentação — é diretamente proporcional à qualidade das entradas.

Quando uma camada está fraca (PRD vago, AGENTS genérico, Skills mal definidas), o agente preenche a incerteza com inferência própria. Isso pode ser bom ou muito ruim, dependendo do contexto. É preferível especificar do que confiar em inferência.

04 / Arquitetura — AGENTS.md

AGENTS.md — O Contrato Vivo

AGENTS.md é um padrão aberto para comunicar aos AI agents o contexto, regras e comportamentos esperados de um repositório. Posicionado na raiz do projeto, é lido por várias ferramentas e agentes (dependendo do produto/integração), servindo como um "README para agentes".

Localização

Sempre na raiz do repositório — ./AGENTS.md

Documento Vivo

Atualizado junto com o projeto, reflete sempre o estado atual.

# AGENTS.md

## Objetivo do Projeto
API REST de gerenciamento de tarefas.

## Stack Tecnológico
- Node.js 22 + TypeScript strict
- Express 5 + Prisma ORM
- PostgreSQL 16
- Vitest para testes

## Convenções de Código
- Nomenclatura: camelCase para variáveis
- Imports: sempre absolutos (src/...)
- Erros: nunca use `any`, use Result types

## DO ✅
- Escreva testes para cada função pública
- Use TypeScript strict mode
- Documente endpoints com JSDoc

## DON'T ❌
- Não use `any` type
- Não faça commit sem testes passando
- Não altere o schema sem migração

AGENTS.md funciona como manual operacional da IA para aquele repositório específico. Linguagem objetiva, regras acionáveis e limites claros — útil para humano e para agente.

Mais de 60 mil repositórios open source já têm um AGENTS.md na raiz. O padrão é stewarded pela Agentic AI Foundation (Linux Foundation), e compatível com a maioria dos agentes de código do mercado.

Dica prática: comece com 20-30 linhas. AGENTS.md de 500 linhas que ninguém mantém é pior do que um de 30 linhas sempre atualizado. Tamanho não é qualidade — clareza é.

04 / Arquitetura — Rules

Rules — Diretrizes Globais

Rules são diretrizes globais que definem o comportamento padrão do agente para todo o workspace, independente do projeto ou tarefa específica.

📌 Cada agente expõe Rules de um jeito: Copilot usa .github/copilot-instructions.md; Codex prioriza AGENTS.md; outros agentes podem usar arquivos próprios.
As Rules são o "modo padrão" do agente. AGENTS.md pode sobrescrever Rules para um projeto específico.

DO — Sempre fazer

  • Use TypeScript strict mode
  • Escreva testes para funções públicas
  • Documente APIs com OpenAPI/JSDoc
  • Siga os padrões SOLID e Clean Code
  • Valide inputs em toda boundary externa

DON'T — Nunca fazer

  • Usar any type no TypeScript
  • Commitar sem testes passando
  • Hardcodar credenciais ou segredos
  • Ignorar erros silenciosamente (empty catch)

Diferenciação simples: Rules são política global do workspace; AGENTS.md é contrato local do projeto. Rules valem sempre; AGENTS.md pode sobrescrever para um contexto específico.

No GitHub Copilot, copilot-instructions.md é o ponto principal de Rules globais. No Codex, AGENTS.md funciona como contrato operacional do repositório. Em outros agentes, o nome muda, mas o princípio continua: instruções globais e locais precisam estar alinhadas.

Quando os dois estão alinhados, você ganha consistência sem perder adaptação contextual. E isso por si só já reduz variação entre sessões e entre membros do time.

04 / Arquitetura — Skills.md

Skills.md — Conhecimento Especializado

Skills são unidades de conhecimento especializado, normalmente organizadas como diretórios com um arquivo SKILL.md como entrypoint. O agente mantém uma descrição curta no contexto e carrega o conteúdo completo apenas quando necessário: Progressive Disclosure na prática.

Performance

Menos tokens consumidos = sessões mais eficientes e baratas.

Portabilidade

Skills funcionam em Codex, Claude Code, Cursor, Gemini CLI e outros AI tools compatíveis.

📖 Ver seção 05 para o aprofundamento em Progressive Disclosure — princípios, estrutura em camadas e boas práticas.
Exemplos reais (clicáveis):
find-skills · vercel-react-best-practices · web-design-guidelines · frontend-design
🎯 Carregue apenas a Skill da tarefa atual para reduzir ruído e tokens no contexto.

Skills são especialização modular de conhecimento. Em vez de carregar tudo sempre, o agente aprofunda só quando a tarefa exige — isso melhora foco, reduz custo de contexto e aumenta qualidade da resposta.

O padrão agentskills.io é aberto e portável. Uma Skill bem escrita pode funcionar em Codex, Claude Code, Cursor, Gemini CLI e outros agentes compatíveis — sem reescrita conceitual.

Seta 1 — card Performance: menos tokens = sessões mais eficientes. Seta 2 — card Portabilidade: mesma Skill em múltiplos agentes. Fechamento: carregar contexto sob demanda é a prática de Progressive Disclosure que exploramos em detalhes na próxima seção.

Os quatro pilares: PRD define o que e por que — intenção de produto. AGENTS.md define como e em qual contexto — contrato de comportamento. Rules são as diretrizes globais independentes de projeto. Skills trazem especialização modular sob demanda.

Com maior autonomia do agente — Agent Mode, execuções longas, tarefas multi-arquivo — mais crítica fica essa arquitetura de contexto. É ela que permite ao agente tomar decisões corretas de forma autônoma sem perguntar a cada passo.

Princípio fundamental: contexto certo, no momento certo, para a tarefa certa. Esse princípio não envelhecerá independente de qual modelo ou agente usar.

05 / Economia de Contexto

Contexto agora tem custo

Usage-based billing muda a conversa: contexto repetido, prompt longo e retrabalho deixam de ser apenas incômodo técnico — viram custo operacional.
  • Input tokens
    Tudo que você envia: prompt, contexto, arquivos e instruções.
  • Output tokens
    Tudo que o modelo devolve: planos, código, explicações e diffs.
  • Cached tokens
    Contexto reaproveitado com precificação própria, conforme documentação oficial.

GitHub AI Credits

A partir de 01/06/2026, interações do Copilot passam a usar billing por consumo. A documentação define 1 GitHub AI Credit = US$0.01.

Não copie tabela de preços para slide: modelos, multiplicadores e allowances mudam. Linke a fonte oficial e revise antes da palestra.

Dados verificados para a edição Maio/2026 na documentação oficial de GitHub Copilot models and pricing. Antes de apresentar, revise a página porque preços, modelos e multiplicadores podem mudar.

A mensagem não é "não use Copilot" nem "use Codex". A mensagem é: quando agentes são cobrados por uso, contexto vira orçamento. Progressive Disclosure passa a ser disciplina técnica e econômica.

Conecte com SDD: PRD claro reduz prompt repetido; AGENTS enxuto reduz ruído; Skills carregadas sob demanda reduzem contexto irrelevante; checks evitam ciclos caros de retrabalho.

05 / Economia de Contexto — Práticas

Economia de tokens: o que funciona

Contexto sob demanda

PRD, AGENTS.md e Skills carregam a informação certa quando a tarefa precisa dela.

Cache e prefixos estáveis

Instruções estáveis no começo do contexto aumentam chance de reaproveitamento por prompt caching.

Modelo certo

Nem toda tarefa precisa do modelo mais caro: classifique risco, complexidade e necessidade de raciocínio.

Saída curta

Concisão reduz output tokens. Caveman é um exemplo prático, mas não elimina custo de reasoning e ferramentas.

Batch e flex

Tarefas assíncronas podem usar processamento mais econômico quando a latência não é crítica.

Observabilidade

Meça input, output, cached tokens, modelo usado, retrabalho e custo por execução.

Regra prática: economizar tokens não é apenas escrever menos. É reduzir ambiguidade, repetição, loops longos e contexto irrelevante.

Este slide amplia a conversa além do billing de uma ferramenta. Economizar tokens envolve arquitetura de contexto, cache, roteamento de modelo, concisão de saída, processamento assíncrono e medição.

Sobre Caveman: apresente como exemplo de output discipline e compressão de linguagem. O cuidado é explicar que respostas mais curtas não garantem redução total quando o maior custo vem de reasoning tokens, tool calls, leitura de arquivos e geração de código.

Conecte com fontes oficiais: OpenAI cost optimization e prompt caching; Anthropic prompt caching e token-efficient tool use; GitHub billing para o contexto de Copilot; Caveman como referência comunitária experimental.

05 / Economia de Contexto — SDD

SDD como FinOps de agentes

Spec clara reduz desperdício

  • Menos prompts repetidos para explicar a mesma intenção.
  • Menos iterações longas para corrigir requisito implícito.
  • Menos tool calls exploratórias porque o critério já está definido.

Anti-patterns caros

  • Prompt gigante copiado em toda sessão.
  • Logs inteiros e outputs de ferramentas sem filtragem.
  • Modelo caro para triagem simples ou tarefa mecânica.
SDD não é só qualidade de entrega. Em agentes, spec boa também é controle de custo, latência, risco e previsibilidade.

FinOps aqui é uma metáfora prática: não transformar a palestra em orçamento, mas mostrar que cada decisão de contexto tem impacto econômico quando agentes passam a consumir tokens, ferramentas e tempo de execução.

A spec atua como contrato e como mecanismo de redução de desperdício. Se o agente sabe objetivo, limites, critérios de aceitação e validação, ele explora menos e corrige menos.

Feche preparando o próximo slide: Progressive Disclosure é a técnica que operacionaliza essa economia sem empobrecer o contexto.

05 / Progressive Disclosure

Progressive Disclosure

Progressive Disclosure é o princípio de revelar apenas o contexto necessário para a tarefa atual. Em SDD, isso significa dividir o conhecimento do agente em camadas — carregando informação especializada sob demanda, economizando tokens, reduzindo ruído e diminuindo retrabalho.

  • AGENTS.md raiz: mínimo, global, estável — regras que valem para todas as tarefas
  • Skills especializadas: carregadas sob demanda, apenas quando necessário
  • Context Window: até 70% de economia de tokens (ref. LinkedIn — Glaucia Lemos)
  • Qualidade: menos ruído = respostas mais precisas e consistentes

Analogia

Como um médico especialista — o clinico geral cuida do básico; o especialista é chamado apenas quando o problema exige. O contexto funciona igual: carregue o especialista só quando precisar.

📊 AGENTS.md minimalista + Skills sob demanda pode reduzir em até 70% o uso de context window por sessão. (ref. LinkedIn — Glaucia Lemos)

↓ pressione ↓ para continuar nesta seção

Progressive Disclosure é sobre foco: carregar apenas o contexto necessário para a tarefa atual. Estratégia prática: base global mínima mais especialização sob demanda.

Isso reduz ruído, melhora assertividade da resposta e reduz custo de tokens por sessão. Menos ruído no contexto significa menos inferência necessária por parte do modelo, o que tende a resultar em output mais próximo da intenção.

Sobre os "até 70% de economia": é uma referência do meu próprio fluxo de trabalho documentado no artigo no LinkedIn (link na seção de referências). Não é pesquisa universal de mercado — é um resultado que vale como referência de campo. Cada time terá seu número; o ponto correto é: otimizar contexto de entrada é prática de engenharia mensurável, não intuição.

Seta 1 — AGENTS raiz mínimo e estável. Seta 2 — Skills sob demanda. Seta 3 — economia de tokens como resultado. Seta 4 — ganho de qualidade de resposta. Fechamento: menos ruído = respostas mais consistentes e previsíveis.

AGENTS.md — Exemplo Minimalista

# AGENTS.md

## Projeto
API de gerenciamento de tarefas com JWT.

## Regras Globais
- TypeScript strict mode
- Testes obrigatórios para funções públicas
- Nunca use `any` type

## Instruções Especializadas
- Testes: docs/agents/testing.md
- Arquitetura: docs/agents/architecture.md
- Segurança: docs/agents/security.md

## Limites do Agente
- Não altere o schema sem migração
- Não faça commit sem testes passando
💡 A IA gera os arquivos especializados automaticamente — você não precisa criá-los manualmente!

Estrutura em camadas é simples de replicar e, mais importante, de manter. AGENTS enxuto na raiz com links para especialização por domínio — testing, arquitetura, segurança, convenções. Rules globais separadas. Skills como unidades de especialização carregadas sob demanda.

O resultado é um arquivo de contexto que ninguém vai se recusar a manter atualizado, porque é pequeno e objetivo. Arquivos monolíticos tendem a ficar desatualizados; arquivos curtos com links são mais fáceis de cuidar.

Detalhe útil: a IA pode gerar os arquivos especializados automaticamente quando você inicializa o projeto. Você fornece o contexto, ela estrutura os arquivos — você revisa e ajusta.

05 / Progressive Disclosure — Princípios

6 Princípios do Progressive Disclosure

1. Minimalismo

AGENTS.md deve conter apenas regras necessárias para todas as tarefas do repositório. Regras específicas ficam em arquivos secundários.

2. Separação

Instrução especializada → arquivo secundário (docs/agents/). Nada de "documento gigante" com tudo dentro.

3. Delegação

AGENTS.md raiz declara onde encontrar instruções especializadas via links. O agente busca quando precisar.

4. Acionabilidade

Prefira instruções diretas: "Antes de alterar código, explique o motivo." Evite textos genéricos como "siga boas práticas".

5. Estabilidade

Estruturas de pastas e informações instáveis não devem ir ao AGENTS.md raiz — apenas a arquivos secundários.

6. Economia

Cada token economizado = respostas mais rápidas e baratas. AGENTS.md enxuto eleva qualidade e reduz custo por sessão.

📚 Esses arquivos especializados também são chamados de "Skills" na comunidade de AI Agents (Claude Code, Cursor, etc.) — mesmo conceito, carregamento sob demanda.

Esses seis princípios são higiene de contexto. Parecem óbvios quando estão escritos, mas violamos cada um deles regularmente quando construímos AGENTS.md no improviso.

Se eu resumir em uma frase: clareza estrutural reduz custo e aumenta confiabilidade. Instrução genérica como "siga boas práticas" contribui zero para o agente. Instrução específica como "antes de alterar código de autenticação, explique por que a mudança é necessária" tem efeito real e verificável.

Esses princípios se aplicam também a prompts isolados — contexto bom sempre supera prompt elaborado sem contexto adequado.

Setas 1 a 6: Minimalismo → Separação → Delegação → Acionabilidade → Estabilidade → Economia. Fechamento: clareza estrutural é a prioridade — não volume de instrução.
