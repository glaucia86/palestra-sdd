04 / Progressive Disclosure

Progressive Disclosure

Progressive Disclosure é o princípio de revelar apenas o contexto necessário para a tarefa atual. Em SDD, isso significa dividir o conhecimento do agente em camadas — carregando informação especializada sob demanda, economizando tokens, reduzindo ruído e diminuindo retrabalho.

  • AGENTS.md raiz: mínimo, global e estável — regras válidas para todas as tarefas
  • Skills especializadas: carregadas sob demanda, apenas quando necessário
  • Context Window: até 70% de economia no fluxo medido pela autora
  • Qualidade: menos ruído gera respostas mais precisas e consistentes

Analogia

Como um médico especialista: o clínico geral cuida do básico; o especialista é chamado apenas quando o problema exige. O contexto funciona igual — carregue o especialista só quando precisar.

AGENTS.md minimalista + Skills sob demanda reduz o contexto persistente sem perder profundidade.

Fontes: Agent Skills Specification · estudo da autora

Progressive Disclosure é sobre foco: carregar apenas o contexto necessário para a tarefa atual. A estratégia prática é uma base global mínima mais especialização sob demanda.

Isso reduz ruído, melhora a assertividade da resposta e reduz o custo de tokens por sessão. Menos ruído significa menos inferência necessária por parte do modelo.

Os “até 70%” vêm do fluxo de trabalho da autora documentado no LinkedIn; não são uma promessa universal. Cada time deve medir seu próprio resultado.

Fechamento: menos ruído produz respostas mais consistentes e previsíveis.

04 / Subagents

Isole o Subproblema

Delegar

Uma pergunta delimitada, com entradas e critério de retorno explícitos.

Isolar

Contexto de trabalho separado evita poluir a tarefa principal.

Retornar

Resultado compacto, evidência, incerteza e próximos riscos.

Subagent é um trabalhador isolado; Skill é conhecimento reutilizável; comando nativo pertence a uma superfície.

Subagents ajudam quando o subproblema pode ser isolado e o retorno cabe em um resumo verificável.

Não trate subagent, Agent Skill e comando de produto como sinônimos; eles resolvem responsabilidades diferentes.

Continuidade entre execuções

State &
Memory

Preserve decisões e evidências úteis sem carregar o transcript inteiro.

Depois de isolar trabalho, precisamos decidir o que sobrevive entre execuções.

04 / State & Memory

Preserve Decisões, Não o Transcript Inteiro

State atual

Objetivo, restrições, progresso e próxima decisão.

Memory curada

Fatos e decisões duráveis, com origem e validade.

Evidência

Sucessos repetitivos podem ser resumidos; falhas preservam detalhes.

compaction ≠ clearing ≠ editing ≠ isolation ≠ caching

Memory não é transcript integral. O que sobrevive deve apoiar decisões futuras sem carregar toda a conversa.

Compaction resume, clearing reinicia, editing altera, isolation separa e caching reutiliza processamento; são mecanismos distintos.

04 / Transição para Economia

Do Contexto Certo ao Contexto Sustentável

1 · Curadoria

Context Engineering decide quais fontes podem mudar a decisão atual.

2 · Limites

Context Economy limita contexto, custo, tempo, tentativas e tamanho do diff.

3 · Saída

Sinais de degradação indicam quando concluir, compactar, isolar ou fazer handoff.

Em uma frase: Context Engineering escolhe o que merece entrar; Context Economy define quanto cabe, por quanto tempo e qual sinal encerra o ciclo.

“Bridge” significava apenas uma transição editorial entre duas perguntas. A tela agora explica essa passagem diretamente.

Primeiro curamos o conjunto de informações. Depois colocamos limites operacionais e critérios de saída para que a sessão permaneça verificável.
