02 / spec-kit

spec-kit — O Toolkit do SDD

O spec-kit é um toolkit open source mantido pelo GitHub que permite focar em cenários de produto e resultados previsíveis, em vez de "vibe coding" cada pedaço do zero. Ele operacionaliza o SDD com um CLI e slash commands para agentes IA.

  • Open Source — MIT License · github/spec-kit
  • Mantido pelo GitHub, inspirado na pesquisa de John Lam
  • Specify CLI — installável via uv tool install
  • Artefatos canônicos — spec.md, plan.md e tasks.md
  • Comandos ou Agent Skills conforme a integração escolhida

Missão

"Build high-quality software faster. Focus on product scenarios and predictable outcomes — not vibe coding."

💡 spec-kit ≠ vibe coding. Cada linha de código é rastreada até um requisito aprovado pelo humano.
🤖 Integrações evoluem. Confirme a lista da sua instalação com specify integration list.

Seta 0 (antes de avançar): pessoal, agora saímos do conceito e entramos na ferramenta que operacionaliza SDD de verdade. A ideia é simples: trocar improviso por processo reproduzível.

02 / spec-kit — Instalação

Instalando o spec-kit

Opção 1 — Instalação Permanente (recomendada)

# Instala uma vez, usa em qualquer projeto
uv tool install specify-cli \
  --from git+https://github.com/github/spec-kit.git@vX.Y.Z

# Verifica versão e saúde da instalação
specify self check

Opção 2 — Uso Único (sem instalar)

uvx --from git+https://github.com/github/spec-kit.git@vX.Y.Z \
  specify init <PROJECT_NAME>
📋 Pré-requisitos: Python 3.11+, uv, Git e um agente IA suportado.

Inicializar Projeto

# Novo projeto com GitHub Copilot
specify init meu-projeto --integration copilot

# Projeto atual com Agent Skills para Codex
specify init . --integration codex \
  --integration-options="--skills"

# Descobrir integrações desta instalação
specify integration list
🔧 O specify init configura templates, contexto e comandos ou Agent Skills conforme a integração.

Instalação permanente com `uv tool install` é a abordagem recomendada para uso no dia a dia: instala uma vez, fica disponível em qualquer projeto. O `uvx` é ideal para avaliar sem comprometer o ambiente global.

Pré-requisito essencial: Python 3.11+, `uv` instalado e um agente suportado. A configuração fina varia por agente; por isso a documentação oficial do spec-kit deve ser a referência antes de uma demo ao vivo.

Os parâmetros do specify init variam por integração. specify integration list mostra o que a versão instalada realmente oferece.

Fonte oficial consultada em 2026-07-15: Core Commands e Integrations. Caveat: use uma tag de release real no lugar de vX.Y.Z e confirme opções na sua versão.

02 / spec-kit — Slash Commands

Slash Commands do spec-kit

⚡ Comandos Essenciais (Core)

ComandoFunção
/speckit.constitutionCria os princípios e diretrizes do projeto
/speckit.specifyDefine o que construir (requisitos + user stories)
/speckit.planCria plan.md com arquitetura e escolhas técnicas
/speckit.tasksCria lista de tarefas acionáveis
/speckit.implementExecuta todas as tarefas e constrói o projeto

🔍 Qualidade e Feedback

ComandoFunção
/speckit.clarifyClarifica áreas sub-especificadas (antes do plan)
/speckit.analyzeAnálise de consistência entre artefatos
/speckit.checklistGera checklists de qualidade customizados
/speckit.convergeVerifica completude e acrescenta gaps a tasks.md
🎯 Trabalham no contexto do agente: Após specify init, esses comandos ficam disponíveis diretamente no GitHub Copilot, Codex, Claude Code, Cursor etc.
Nota: em alguns ambientes, os slash commands podem não aparecer; fallback: rodar via CLI e/ou usar templates manualmente.

Exemplo — Agente + spec-kit

/speckit.constitution
  Focar em qualidade de código,
  padrões de testes e consistência
  de UX.

/speckit.specify
  API REST de tarefas com auth
  JWT e PostgreSQL.

/speckit.plan
  Stack: Node.js + TypeScript +
  Prisma.

Aqui está o ciclo completo: constituição → especificação → plano → tarefas → implementação. Cada etapa deixa evidência rastreável e tem gate humano antes de avançar.

Se o slash command não aparecer no painel do agente — o que pode acontecer dependendo da ferramenta, integração ou versão — o CLI funciona igualmente. Processo consistente vence prompt brilhante isolado.

Para a audiência: o `/speckit.clarify` é especialmente útil antes de planejar — clarifica áreas sub-especificadas antes que virem código errado.

Depois da implementação, /speckit.converge verifica completude e adiciona a tasks.md o trabalho restante; se houver gaps, o ciclo volta para implementação.

Fonte oficial consultada em 2026-07-15: README do spec-kit e Evolving Specs. Caveat: a forma de invocação pode ser slash command ou Agent Skill, conforme a integração.

02 / spec-kit — Fluxo SDD

Fluxo SDD com spec-kit

Init specify init
Constituição /speckit.constitution
Especificação /speckit.specify
Planejamento /speckit.plan
Tarefas /speckit.tasks
Implementar /speckit.implement
Convergir /speckit.converge
↩ gaps → implementar
📌 Feedback loop: use /speckit.analyze antes de implementar; depois, /speckit.converge acrescenta gaps a tasks.md e o ciclo se repete com revisão humana.

O fluxo mantém os artefatos vivos: constituição, spec, plano e tarefas orientam a implementação, e a implementação volta a ser comparada com eles.

/speckit.analyze é um quality check recomendado entre tarefas e implementação. /speckit.converge verifica completude e acrescenta gaps a tasks.md; havendo trabalho restante, repetimos implement → converge.

Os ícones de humano não são decorativos: cada mudança de artefato e cada novo lote de tarefas precisa de revisão antes de seguir.

Fonte oficial consultada em 2026-07-15: Evolving Specs. Caveat: converge fecha gaps; ele não substitui aprovação humana nem garante qualidade sozinho.

02 / spec-kit — Artefatos

Artefatos Canônicos

A intenção humana vira uma cadeia rastreável: spec define o que e por quê; plan registra arquitetura e escolhas técnicas; tasks organiza a execução.

.specify/memory/constitution.md
specs/<feature>/
├── spec.md    # what / why
├── plan.md    # arquitetura / tech
└── tasks.md   # execução rastreável
📋 Um PRD.md existente pode ser entrada ou referência; não é output canônico obrigatório de /speckit.plan.
ComandoArtefato / intenção
constitutionprincípios e governança
specifyspec.md: what / why
planplan.md: arquitetura e escolhas técnicas
taskstasks.md: execução rastreável
implementmudanças no código
convergegaps acrescentados a tasks.md

Este slide corrige uma distinção importante: /speckit.plan cria o plano técnico, não um PRD canônico.

Um PRD existente pode enriquecer a entrada, mas os artefatos operacionais do fluxo são constituição, spec.md, plan.md e tasks.md, seguidos pelo código e pela convergência.

Fonte oficial consultada em 2026-07-15: README do spec-kit e spec-driven.md. Caveat: extensões e presets podem acrescentar artefatos, sem mudar o papel dos artefatos core.

02 / spec-kit — Agent Skills

Agent Skills + SKILL.md

Pacote portátil

Cada skill vive em um diretório próprio, com instruções no arquivo obrigatório SKILL.md.

Instalação

Integrações compatíveis aceitam --integration-options="--skills" para gerar Agent Skills.

Invocação

O nome e a sintaxe variam por agente; o conteúdo da skill preserva a intenção do comando spec-kit.

speckit-plan/ → SKILL.md + recursos opcionais. Consulte a integração para caminho e forma de chamada.

Agent Skills empacotam instruções reutilizáveis em diretórios cujo ponto de entrada é SKILL.md. O spec-kit pode gerar esse formato para integrações compatíveis.

A sintaxe de invocação não é universal: algumas superfícies usam slash commands; outras usam nomes de skill. O contrato durável é o diretório da skill e seu SKILL.md.

Fonte oficial consultada em 2026-07-15: README do spec-kit e Integrations. Caveat: suporte a skills, diretório e sintaxe de chamada dependem da integração e da versão instalada.
