02 / spec-kit

spec-kit — O Toolkit do SDD

O spec-kit é um toolkit open source mantido pelo GitHub que permite focar em cenários de produto e resultados previsíveis, em vez de "vibe coding" cada pedaço do zero. Ele operacionaliza o SDD com um CLI e slash commands para agentes IA.

  • Open Source — MIT License · github/spec-kit
  • +70k estrelas no GitHub · +80 contribuidores
  • Mantido pelo GitHub, inspirado na pesquisa de John Lam
  • Specify CLI — installável via uv tool install
  • Slash Commands via integração do agente (/speckit.*, quando suportado)

Missão

"Build high-quality software faster. Focus on product scenarios and predictable outcomes — not vibe coding."

💡 spec-kit ≠ vibe coding. Cada linha de código é rastreada até um requisito aprovado pelo humano.
🤖 Compatível com: GitHub Copilot, Claude Code, Cursor, Gemini CLI, Windsurf, Codex CLI e +20 agentes!

02 / spec-kit — Instalação

Instalando o spec-kit

Opção 1 — Instalação Permanente (recomendada)

# Instala uma vez, usa em qualquer projeto
uv tool install specify-cli \
  --from git+https://github.com/github/spec-kit.git

# Verifica ferramentas disponíveis
specify check

Opção 2 — Uso Único (sem instalar)

uvx --from git+https://github.com/github/spec-kit.git \
  specify init <PROJECT_NAME>
📋 Pré-requisitos: Python 3.11+, uv, Git e um agente IA suportado.

Inicializar Projeto

# Novo projeto com GitHub Copilot
specify init meu-projeto --ai copilot

# Em projeto existente
specify init --here --ai copilot

# Windows (PowerShell)
specify init meu-projeto --ai copilot --script ps

# Com AI Skills integradas
specify init meu-projeto --ai copilot --ai-skills

# Com Claude Code
specify init meu-projeto --ai claude
🔧 O specify init configura: templates, slash commands (/speckit.*) e estrutura de pastas automaticamente.

Eu apresento esta parte como receita: pré-requisito, instalação e inicialização. Simples, mas com padrão claro para todo o time.

Instalação permanente funciona melhor para quem usa todo dia. Uso com uvx é bom para testar sem acoplamento.

Também vale reforçar que os parâmetros mudam por agente e shell.

02 / spec-kit — Slash Commands

Slash Commands do spec-kit

⚡ Comandos Essenciais (Core)

ComandoFunção
/speckit.constitutionCria os princípios e diretrizes do projeto
/speckit.specifyDefine o que construir (requisitos + user stories)
/speckit.planGera plano técnico de implementação (≈ PRD)
/speckit.tasksCria lista de tarefas acionáveis
/speckit.implementExecuta todas as tarefas e constrói o projeto

🔍 Comandos Opcionais

ComandoFunção
/speckit.clarifyClarifica áreas sub-especificadas (antes do plan)
/speckit.analyzeAnálise de consistência entre artefatos
/speckit.checklistGera checklists de qualidade customizados
🎯 Trabalham no contexto do agente: Após specify init, esses comandos ficam disponíveis diretamente no GitHub Copilot Chat, Claude Code, Cursor etc.
Nota: em alguns ambientes, os slash commands podem não aparecer; fallback: rodar via CLI e/ou usar templates manualmente.

Exemplo — Copilot + spec-kit

/speckit.constitution
  Focar em qualidade de código,
  padrões de testes e consistência
  de UX.

/speckit.specify
  API REST de tarefas com auth
  JWT e PostgreSQL.

/speckit.plan
  Stack: Node.js + TypeScript +
  Prisma.

Aqui está o ciclo completo: definir, planejar, quebrar em tarefas e implementar. Isso reduz improviso porque cada etapa deixa evidência.

Se o slash command não aparecer no ambiente, sem problema: o CLI continua sendo caminho oficial.

Mensagem-chave para a audiência: processo consistente vence prompt brilhante isolado.

02 / spec-kit — Fluxo SDD

Fluxo SDD com spec-kit

Init specify init
Constituição /constitution
Especificação /specify
Planejamento /plan
✅ Aprovação gate humano
↩ reprovado → /plan
Tarefas /tasks
Implementar /implement
📌 Human-in-the-Loop: cada artefato gerado pelo spec-kit é revisado por você antes de avançar. A IA executa, o humano valida, corrige e aprova.

Este slide é sobre controle de risco. O gate humano existe para impedir que plano ruim vire código em produção.

Se não aprovou, volta para plan. Esse loop parece lento no curto prazo, mas economiza muito custo de correção depois.

02 / spec-kit — PRD.md

PRD.md — Ponto de Partida

Você idealiza o projeto e cria via prompt o PRD.md. Em seguida, usa um prompt junto com /speckit.specify para que o agente leia esse arquivo e inicie o ciclo: specify → plan → tasks → implement.

# PRD: [Nome do Projeto]

## 1. Visão Geral
Descrição concisa do produto e objetivos.

## 2. Requisitos Funcionais
- **RF01**: O sistema deve...
- **RF02**: O sistema deve...

## 3. Requisitos Não-Funcionais
Performance, segurança, acessibilidade.

## 4. Critérios de Aceite
- **CA01**: Testável e verificável...

## 5. Perguntas Abertas
- Ambiguidades a resolver...
Por que PRD.md importa para a IA?
  • Use IDs únicos RF01, CA01 para rastreabilidade
  • Critérios de aceite testáveis e objetivos
  • Versionado no Git — histórico de decisões
  • Lido por humanos e máquinas
Sem PRD.mdCom PRD.md
Contexto vago e efêmeroContexto estruturado e persistente
Alucinações frequentesAlucinações drasticamente reduzidas
Rastreabilidade impossívelAutomática via IDs (RF, CA)
Onboarding lentoRápido via PRD.md + AGENTS.md

PRD é contrato de produto legível por humano e por agente. Quando RF e CA estão claros e testáveis, a implementação fica muito menos ambígua.

IDs de requisito e aceite são essenciais para rastrear código, teste e decisão ao longo do tempo.

02 / spec-kit — Checklist Operacional

Mini Checklist de Qualidade (Spec → Plan → Tasks)

Spec

  • Objetivos + não-objetivos explícitos
  • Critérios de aceitação testáveis
  • Exemplos e edge cases relevantes

Plan

  • Decomposição incremental por etapas
  • Dependências e riscos mapeados
  • Gate de revisão humana antes de implementar

Tasks

  • Small batches (mudanças pequenas)
  • Verificação a cada lote (teste/lint/build)
  • Evidência de conclusão por tarefa
✅ Se o checklist passa, o agente ganha velocidade sem perder confiabilidade.

Este e o checklist de \"pronto para executar\". Se spec, plan e tasks passam aqui, a chance de retrabalho cai bastante.

Eu gosto de vender este ritual como seguro barato: poucos minutos de revisão para evitar horas de correção.
