02 / spec-kit

spec-kit — The SDD Toolkit

The spec-kit is an open-source toolkit maintained by GitHub that helps teams focus on product scenarios and predictable outcomes, instead of vibe-coding every piece from scratch. It operationalizes SDD with a CLI and slash commands for AI agents.

  • Open Source — MIT License · github/spec-kit
  • +70k stars on GitHub · 79 contributors
  • Maintained by GitHub, inspired by John Lam's research
  • Specify CLI — installable via uv tool install
  • Slash Commands through agent integration (/speckit.*, when supported)

Mission

"Build high-quality software faster. Focus on product scenarios and predictable outcomes — not vibe coding."

💡 spec-kit ≠ vibe coding. Every line of code is traceable to a human-approved requirement.
🤖 Compatible with: GitHub Copilot, Claude Code, Cursor, Gemini CLI, Windsurf, Codex CLI, and 20+ agents!

02 / spec-kit - Installation

Installing spec-kit

Option 1 - Permanent installation (recommended)

# Install once, use in any project
uv tool install specify-cli \
  --from git+https://github.com/github/spec-kit.git

# Check available tools
specify check

Option 2 - One-time use (no install)

uvx --from git+https://github.com/github/spec-kit.git \
  specify init <PROJECT_NAME>
📋 Prerequisites: Python 3.11+, uv, Git, and a supported AI agent.

Initialize Project

# New project with GitHub Copilot
specify init my-project --ai copilot

# In an existing project
specify init --here --ai copilot

# Windows (PowerShell)
specify init my-project --ai copilot --script ps

# With integrated AI Skills
specify init my-project --ai copilot --ai-skills

# With Claude Code
specify init my-project --ai claude
🔧 specify init sets up templates, slash commands (/speckit.*), and folder structure automatically.
02 / spec-kit — Slash Commands

spec-kit Slash Commands

⚡ Essential Commands (Core)

CommandFunction
/speckit.constitutionCreates project principles and guidelines
/speckit.specifyDefines what to build (requirements + user stories)
/speckit.planGenerates the technical implementation plan (≈ PRD)
/speckit.tasksCreates an actionable task list
/speckit.implementExecutes all tasks and builds the project

🔍 Optional Commands

CommandFunction
/speckit.clarifyClarifies underspecified areas (before plan)
/speckit.analyzeConsistency analysis across artifacts
/speckit.checklistGenerates customized quality checklists
🎯 Run in agent context: after specify init, these commands become available directly in GitHub Copilot Chat, Claude Code, Cursor, etc.
Note: in some environments slash commands may not appear; fallback: run via CLI and/or use templates manually.

Example — Copilot + spec-kit

/speckit.constitution
  Focus on code quality,
  testing standards, and
  UX consistency.

/speckit.specify
  Task REST API with auth
  JWT and PostgreSQL.

/speckit.plan
  Stack: Node.js + TypeScript +
  Prisma.

02 / spec-kit — PRD.md

PRD.md — Starting Point

You shape the project and create the PRD.md via prompt. Then use a prompt with /speckit.specify so the agent reads that file and starts the cycle: specify → plan → tasks → implement.

# PRD: [Project Name]

## 1. Overview
Concise product description and goals.

## 2. Functional Requirements
- **FR01**: The system must...
- **FR02**: The system must...

## 3. Non-Functional Requirements
Performance, security, accessibility.

## 4. Acceptance Criteria
- **AC01**: Testable and verifiable...

## 5. Open Questions
- Ambiguities to resolve...
Why does PRD.md matter for AI?
  • Use unique IDs FR01, AC01 for traceability
  • Objective, testable acceptance criteria
  • Versioned in Git — decision history
  • Readable by humans and machines
Without PRD.mdWith PRD.md
Vague, ephemeral contextStructured, persistent context
Frequent hallucinationsDrastically reduced hallucinations
No traceabilityAutomatic via IDs (FR, AC)
Slow onboardingFast via PRD.md + AGENTS.md
02 / spec-kit — Operational Checklist

Mini Quality Checklist (Spec → Plan → Tasks)

Spec

  • Explicit goals + non-goals
  • Testable acceptance criteria
  • Relevant examples and edge cases

Plan

  • Incremental staged decomposition
  • Dependencies and risks mapped
  • Human review gate before implementation

Tasks

  • Small batches (small changes)
  • Verification per batch (test/lint/build)
  • Completion evidence per task
✅ If the checklist passes, the agent gains speed without losing reliability.
