02 / spec-kit

spec-kit — The SDD Toolkit

The spec-kit is an open-source toolkit maintained by GitHub that helps teams focus on product scenarios and predictable outcomes, instead of vibe-coding every piece from scratch. It operationalizes SDD with a CLI and slash commands for AI agents.

  • Open Source — MIT License · github/spec-kit
  • Maintained by GitHub, inspired by John Lam's research
  • Specify CLI — installable via uv tool install
  • Canonical artifacts — spec.md, plan.md, and tasks.md
  • Commands or Agent Skills depending on the selected integration

Mission

"Build high-quality software faster. Focus on product scenarios and predictable outcomes — not vibe coding."

💡 spec-kit ≠ vibe coding. Every line of code is traceable to a human-approved requirement.
🤖 Integrations evolve. Check your installation with specify integration list.

02 / spec-kit - Installation

Installing spec-kit

Option 1 - Permanent installation (recommended)

# Install once, use in any project
uv tool install specify-cli \
  --from git+https://github.com/github/spec-kit.git@vX.Y.Z

# Check version and installation health
specify self check

Option 2 - One-time use (no install)

uvx --from git+https://github.com/github/spec-kit.git@vX.Y.Z \
  specify init <PROJECT_NAME>
📋 Prerequisites: Python 3.11+, uv, Git, and a supported AI agent.

Initialize Project

# New project with GitHub Copilot
specify init my-project --integration copilot

# Current project with Agent Skills for Codex
specify init . --integration codex \
  --integration-options="--skills"

# Discover integrations in this installation
specify integration list
🔧 specify init sets up templates, context, and commands or Agent Skills for the integration.

The practical part: two installation modes. Recommended using uv tool install for a permanent installation.

specify init prepares everything the agent needs: instructions, templates, folder structure. After that, the agent already has the minimum context to start the cycle.

Use specify integration list to see what the installed version actually supports; integration options are not universal.

02 / spec-kit — Slash Commands

spec-kit Slash Commands

⚡ Essential Commands (Core)

CommandFunction
/speckit.constitutionCreates project principles and guidelines
/speckit.specifyDefines what to build (requirements + user stories)
/speckit.planCreates plan.md with architecture and technical choices
/speckit.tasksCreates an actionable task list
/speckit.implementExecutes all tasks and builds the project

🔍 Quality and Feedback

CommandFunction
/speckit.clarifyClarifies underspecified areas (before plan)
/speckit.analyzeConsistency analysis across artifacts
/speckit.checklistGenerates customized quality checklists
/speckit.convergeChecks completeness and appends gaps to tasks.md
🎯 Run in agent context: after specify init, these commands become available directly in GitHub Copilot Chat, Claude Code, Cursor, etc.
Note: in some environments slash commands may not appear; fallback: run via CLI and/or use templates manually.

Example — Copilot + spec-kit

/speckit.constitution
  Focus on code quality,
  testing standards, and
  UX consistency.

/speckit.specify
  Task REST API with auth
  JWT and PostgreSQL.

/speckit.plan
  Stack: Node.js + TypeScript +
  Prisma.

The slash commands are spec-kit's operational interface inside the agent. The logical sequence is: constitution → specify → plan → tasks → implement.

In practice, not all agent environments support slash commands. The fallback is to use the CLI and templates manually — the result is the same, the flow is equivalent.

Arrow 1 — Core commands: constitution, specify, plan, tasks, implement. Arrow 2 — Optional commands: clarify, analyze, checklist. Closing: the command only works well if the context (PRD, constitution) comes first.

After implementation, /speckit.converge checks completeness and appends remaining work to tasks.md; when gaps remain, the cycle returns to implementation.

02 / spec-kit — SDD Flow

SDD Flow with spec-kit

Init specify init
Constitution /speckit.constitution
Specification /speckit.specify
Planning /speckit.plan
Tasks /speckit.tasks
Implement /speckit.implement
Converge /speckit.converge
↩ gaps → implement
📌 Feedback loop: use /speckit.analyze before implementation; then /speckit.converge appends gaps to tasks.md and the cycle repeats with human review.

The flow keeps artifacts alive: constitution, spec, plan, and tasks guide implementation, and implementation is compared back against them.

/speckit.analyze is a recommended quality check between tasks and implementation. /speckit.converge checks completeness and appends gaps to tasks.md; if work remains, repeat implement → converge.

The human icons are not decorative: artifact changes and new task batches still require review before proceeding.

Official source consulted on 2026-07-15: Evolving Specs. Caveat: converge closes gaps; it does not replace human approval or guarantee quality by itself.

02 / spec-kit — Artifacts

Canonical Artifacts

Human intent becomes a traceable chain: the spec defines what and why; the plan records architecture and technical choices; tasks organize execution.

.specify/memory/constitution.md
specs/<feature>/
├── spec.md    # what / why
├── plan.md    # architecture / tech
└── tasks.md   # traceable execution
📋 An existing PRD.md can be an input or reference; it is not a required canonical output of /speckit.plan.
CommandArtifact / intent
constitutionprinciples and governance
specifyspec.md: what / why
planplan.md: architecture and technical choices
taskstasks.md: traceable execution

This slide corrects an important distinction: /speckit.plan creates the technical plan, not a canonical PRD.

An existing PRD can enrich the input, but the operational artifacts are the constitution, spec.md, plan.md, and tasks.md, followed by code and convergence.

02 / spec-kit — Agent Skills

Agent Skills + SKILL.md

Portable package

Each skill lives in its own directory, with instructions in the required SKILL.md entry point.

Installation

Compatible integrations accept --integration-options="--skills" to scaffold Agent Skills.

Invocation

Names and syntax vary by agent; the skill content preserves the intent of the spec-kit command.

speckit-plan/ → SKILL.md + optional resources. Check the integration for its path and invocation style.

Agent Skills package reusable instructions in directories whose entry point is SKILL.md. Spec-kit can generate this format for compatible integrations.

Invocation is not universal: some surfaces use slash commands, while others use skill names. The durable contract is the skill directory and its SKILL.md.

Official sources consulted on 2026-07-15: spec-kit README and Integrations. Caveat: skills support, directories, and invocation syntax depend on the integration and installed version.
