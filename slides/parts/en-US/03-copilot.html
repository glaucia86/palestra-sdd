03 / GitHub Copilot Chat — Modes

The 4 Copilot Chat Modes

Ask Mode

Conversational mode: ask questions, get explanations, discuss architecture. Copilot responds but does not edit files. Ideal for exploration.

Edit Mode

Direct, focused edits in the editor — inline, multi-file, or via Ctrl+I. Ideal for quick iterations without leaving the code context.

Agent Mode ✦

Autonomous mode — runs end-to-end tasks: analyzes the codebase, decides which files to change, runs terminal commands, and iterates until done. The ideal mode for SDD.

Plan Mode

Copilot creates a detailed implementation plan for human review before any code change. Perfect for SDD.

Ask → Plan → Agent: understand the codebase, create the plan, execute with structured context. The full SDD flow.

The four modes have a natural SDD progression: Ask to understand context, Edit for quick targeted changes, Plan to review before editing, Agent for full autonomous execution.

In practice for SDD: start with Ask to understand the codebase → use Plan to map what will be changed → unlock Agent Mode to execute with a structured PRD.md as context. Never start with Agent Mode without a validated plan.

Arrow 1 — Ask Mode (exploration). Arrow 2 — Edit Mode (targeted edits). Arrow 3 — Plan Mode (human review before execution). Arrow 4 — Agent Mode (autonomous execution). Closing: the workflow Ask → Plan → Agent is the native SDD flow inside the IDE.

03 / GitHub Copilot — Agent Skills

Agent Skills — Dec/2025

GitHub Copilot natively supports Agent Skills — directories with a SKILL.md entrypoint, following the open agentskills.io pattern introduced by Anthropic for Claude Code and adopted by GitHub in Dec/2025.

  • Open standard: agentskills.io — directory spec with SKILL.md
  • Auto-discovery: Copilot scans .github/skills/ automatically
  • Progressive Disclosure: description always in context; full skill loaded on demand
  • Portability: same pattern works in Claude Code, Cursor, Gemini CLI, and other agents
  • VS Code: create Skills via chat — "@copilot create a skill for React patterns"

Skill Structure

.github/
└── skills/
    └── react-patterns/
        ├── SKILL.md        ← entrypoint
        ├── hooks.md
        └── examples/

SKILL.md — Entrypoint

---
name: react-patterns
description: React component patterns
  with hooks, Context API, and performance.
---

Load this skill when working
with React components. Includes:
hooks, Context, memo, lazy.

Agent Skills are a powerful context layer introduced in December 2025. Instead of overloading the agent with the full codebase, you load only the skill relevant to the current task — React patterns, TypeScript conventions, API design, etc.

The SKILL.md entrypoint is read on-demand, not loaded into every prompt. This is the "progressive disclosure" of context: give the agent exactly what it needs, when it needs it.

Arrow 1 — skill folder structure. Arrow 2 — SKILL.md format and on-demand loading. Closing: skills are the mechanism that makes spec-kit's `--ai-skills` flag valuable — structured, modular, loadable context.

03-F / Codex — Security

Sandbox, Approvals, and Trust

Sandbox

  • read-only: inspection without mutation.
  • workspace-write: edits inside the workspace.
  • danger-full-access: only in isolated environments.

Approvals

  • on-request: asks before leaving the sandbox.
  • never: does not pause for approval.
  • untrusted: requires approval for mutations.
Autonomy without limits becomes risk. The right harness defines where the agent can read, write, and execute. 
# Practical preset for local work

# --ask-for-approval on-request

03-H / Codex — Automation

codex exec and SDD Automation

codex exec is Codex non-interactive mode for scripts, CI/CD, and repeatable tasks. In SDD, use it only when the spec, limits, and validation are clear.

  • --full-auto: allows low-friction workspace edits.
  • --json: emits JSONL events for automation.
  • --output-last-message: saves the final answer.
  • --output-schema: validates structured output.
  • Prompts, logs, and tool output can contain sensitive data.

Safe example

codex exec --full-auto \
  --json \
  --output-last-message summary.md \
  "Read PRD.md, implement only
   FR01, run tests, then stop."
Avoid danger-full-access outside isolated runners. Good automation starts with small scope and objective checks.
