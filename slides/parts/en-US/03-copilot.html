03 / GitHub Copilot Chat — Modes

The 4 Copilot Chat Modes

Ask Mode

Conversational mode: ask questions, get explanations, discuss architecture. Copilot responds but does not edit files. Ideal for exploration.

Edit Mode

Direct, focused edits in the editor — inline, multi-file, or via Ctrl+I. Ideal for quick iterations without leaving the code context.

Agent Mode ✦

Autonomous mode — runs end-to-end tasks: analyzes the codebase, decides which files to change, runs terminal commands, and iterates until done. The ideal mode for SDD.

Plan Mode

Copilot creates a detailed implementation plan for human review before any code change. Perfect for SDD.

Ask → Plan → Agent: understand the codebase, create the plan, execute with structured context. The full SDD flow.

The four modes have a natural SDD progression: Ask to understand context, Edit for quick targeted changes, Plan to review before editing, Agent for full autonomous execution.

In practice for SDD: start with Ask to understand the codebase → use Plan to map what will be changed → unlock Agent Mode to execute with a structured PRD.md as context. Never start with Agent Mode without a validated plan.

Arrow 1 — Ask Mode (exploration). Arrow 2 — Edit Mode (targeted edits). Arrow 3 — Plan Mode (human review before execution). Arrow 4 — Agent Mode (autonomous execution). Closing: the workflow Ask → Plan → Agent is the native SDD flow inside the IDE.

03 / GitHub Copilot Chat — Features

Main Features

Participants (@)

  • @workspace — whole-project context
  • @vscode — editor commands and settings
  • @terminal — terminal help
  • @github — PRs, issues, web search

Slash Commands (/)

  • /explain — explains selected code
  • /fix — fixes bugs automatically
  • /tests — generates unit tests
  • /doc — documents functions and APIs

Chat Variables (#)

  • #file — attaches file as context
  • #web — real-time web search
  • #selection — focuses on selected snippet
  • #codebase — indexes the entire workspace

MCP Integration

Model Context Protocol — open standard to connect Copilot to external tools: databases, APIs, cloud services. GitHub MCP Server already available.

Image Support

Attach screenshots (JPEG, PNG, GIF, WEBP) to describe UIs, explain architecture diagrams, or analyze visual issues with multimodal models.

Inline Chat

Ctrl+I directly in the editor — edit code without opening the side panel. Refactor any selection with natural language.

Features like @participants, slash commands, and chat variables are the "levers" of context precision. The more precisely you direct Copilot to the relevant context, the better and more predictable the result.

In an SDD workflow: `@workspace #file:PRD.md` is the baseline prompt. Adding `#selection` or `#codebase` as needed. `/tests` after implementing to close the quality loop.

MCP is a game changer for teams: connecting Copilot to databases, cloud APIs, and internal tools turns it from a code assistant into an integrated engineering platform.

Arrow 1 — @participants (scope context). Arrow 2 — slash commands (specific actions). Arrow 3 — chat variables (file/selection context). Arrow 4 — MCP (external tools). Closing: depth of context control is what turns Copilot into a predictable SDD collaborator.

03 / GitHub Copilot — Agent Skills

Agent Skills — Dec/2025

GitHub Copilot natively supports Agent Skills — directories with a SKILL.md entrypoint, following the open agentskills.io pattern introduced by Anthropic for Claude Code and adopted by GitHub in Dec/2025.

  • Open standard: agentskills.io — directory spec with SKILL.md
  • Auto-discovery: Copilot scans .github/skills/ automatically
  • Progressive Disclosure: description always in context; full skill loaded on demand
  • Portability: same pattern works in Claude Code, Cursor, Gemini CLI, and other agents
  • VS Code: create Skills via chat — "@copilot create a skill for React patterns"

Skill Structure

.github/
└── skills/
    └── react-patterns/
        ├── SKILL.md        ← entrypoint
        ├── hooks.md
        └── examples/

SKILL.md — Entrypoint

---
name: react-patterns
description: React component patterns
  with hooks, Context API, and performance.
---

Load this skill when working
with React components. Includes:
hooks, Context, memo, lazy.

Agent Skills are a powerful context layer introduced in December 2025. Instead of overloading the agent with the full codebase, you load only the skill relevant to the current task — React patterns, TypeScript conventions, API design, etc.

The SKILL.md entrypoint is read on-demand, not loaded into every prompt. This is the "progressive disclosure" of context: give the agent exactly what it needs, when it needs it.

Arrow 1 — skill folder structure. Arrow 2 — SKILL.md format and on-demand loading. Closing: skills are the mechanism that makes spec-kit's `--ai-skills` flag valuable — structured, modular, loadable context.

03 / GitHub Copilot Chat — SDD

GitHub Copilot + SDD = 🚀

The spec is the perfect prompt. When you provide GitHub Copilot with a well-structured PRD.md + AGENTS.md, it has the context needed to deliver what you need.
  • PRD.md as primary context via #file
  • AGENTS.md loaded automatically in Agent Mode
  • Agent Mode executes requirement by requirement with traceability
  • Plan Mode creates an implementation plan for human review
  • Iteration guided by PRD acceptance criteria (AC)

Prompt SDD Ideal

@workspace Based on:
- #file:PRD.md (requirements)
- #file:AGENTS.md (context)

Implement FR01 following
exactly acceptance criteria
AC01 and AC02. Write tests to
cover both described scenarios.
🎯 SDD turns vague prompts into precise instructions and GitHub Copilot into a predictable collaborator.

This is the practical integration slide: PRD.md + AGENTS.md as the structured prompt. Note the example in the slide — `@workspace #file:PRD.md #file:AGENTS.md implement FR01 following AC01 and AC02` — this is what a spec-first prompt looks like in practice.

The contrast with unstructured prompts is stark: instead of "build me an authentication system", you have a specific requirement with testable criteria and existing context. The agent's output quality is a direct function of this input quality.

Arrows 1–5: PRD.md as context, AGENTS.md auto-loading, Agent Mode execution, Plan Mode review, iteration by acceptance criteria. Closing: Copilot is only as predictable as the context you give it — SDD provides that context systematically.
