04 / Progressive Disclosure

Progressive Disclosure

Progressive Disclosure is the principle of revealing only the context needed for the current task. In SDD, this means layering the agent's knowledge — loading specialized information on demand, saving tokens, reducing noise, and decreasing rework.

  • Root AGENTS.md: minimal, global, and stable — rules that apply to all tasks
  • Specialized Skills: loaded on demand, only when needed
  • Context Window: up to 70% savings in the author's measured workflow
  • Quality: less noise produces more precise and consistent responses

Analogy

Like a medical specialist: the general practitioner handles the basics; the specialist is called only when the problem requires it. Context works the same way — load the specialist only when needed.

A minimal AGENTS.md + on-demand Skills approach reduces persistent context without losing depth.

Sources: Agent Skills Specification · author's study

Progressive Disclosure is about focus: load only the context needed for the current task. The practical strategy is a minimal global base plus on-demand specialization.

This reduces noise, improves response accuracy, and lowers token cost per session. Less noise means less inference required from the model.

The “up to 70%” figure comes from the author's workflow documented on LinkedIn; it is not a universal promise. Each team should measure its own result.

Closing: less noise produces more consistent and predictable responses.

04 / Subagents

Isolate the Subproblem

Delegate

A bounded question with explicit inputs and return criteria.

Isolate

A separate working context avoids polluting the main task.

Return

A compact result with evidence, uncertainty, and remaining risks.

Subagent is an isolated worker; Skill is reusable knowledge; a native command belongs to a surface.

Subagents help when the subproblem can be isolated and the return fits a verifiable summary.

Do not treat a subagent, an Agent Skill, and a product command as synonyms; they carry different responsibilities.

04 / State & Memory

Preserve Decisions, Not the Entire Transcript

Current state

Goal, constraints, progress, and the next decision.

Curated memory

Durable facts and decisions with source and freshness.

Evidence

Repeated successes may be summarized; failures keep their detail.

compaction ≠ clearing ≠ editing ≠ isolation ≠ caching

Memory is not the complete transcript. What survives should support future decisions without carrying the whole conversation.

Compaction summarizes, clearing restarts, editing changes, isolation separates, and caching reuses computation; they are distinct mechanisms.

04 / Transition to Economy

From the Right Context to Sustainable Context

1 · Curation

Context Engineering decides which sources can change the current decision.

2 · Limits

Context Economy bounds context, cost, time, attempts, and diff size.

3 · Exit

Degradation signals tell us when to finish, compact, isolate, or hand off.

In one sentence: Context Engineering chooses what deserves to enter; Context Economy defines how much fits, for how long, and what signal ends the cycle.
