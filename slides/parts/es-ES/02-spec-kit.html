02 / spec-kit

spec-kit — El Toolkit de SDD

El spec-kit es un toolkit open source de GitHub que operacionaliza SDD con CLI, artefactos y comandos para agentes de IA. Prioriza escenarios de producto y resultados predecibles sobre el "vibe coding".

  • Open Source — MIT License · github/spec-kit
  • Mantenido por GitHub, inspirado en la investigacion de John Lam
  • Specify CLI — instalable via uv tool install
  • Artefactos canónicos — spec.md, plan.md y tasks.md
  • Comandos o Agent Skills por integración

Mision

"Build high-quality software faster. Focus on product scenarios and predictable outcomes — not vibe coding."

💡 spec-kit ≠ vibe coding. Cada linea de codigo se rastrea hasta un requisito aprobado por una persona.
🤖 Las integraciones evolucionan. Comprueba tu instalación con specify integration list.

↓ presiona ↓ para continuar en esta seccion

spec-kit operacionaliza el SDD: en lugar de hacer prompts por impulso, el ciclo comienza con la especificación. La CLI y los slash commands garantizan que el flujo sea repetible — cualquier miembro del equipo trabaja del mismo modo.

Enfatizar que esto no es un framework teórico: es código instalable que el equipo puede adoptar ahora mismo.

Flecha 1 — spec-kit en GitHub. Flecha 2 — CLI (specify). Flecha 3 — Slash commands. Flecha 4 — +20 agentes. Cierre: spec-kit es un puente entre la intención humana y la ejecución del agente.

02 / spec-kit - Instalacion

Instalando spec-kit

Opcion 1 - Instalacion permanente (recomendada)

# Instala una vez, usalo en cualquier proyecto
uv tool install specify-cli \
  --from git+https://github.com/github/spec-kit.git@vX.Y.Z

# Verifica versión y salud de la instalación
specify self check

Opcion 2 - Uso unico (sin instalar)

uvx --from git+https://github.com/github/spec-kit.git@vX.Y.Z \
  specify init <PROJECT_NAME>
📋 Prerequisitos: Python 3.11+, uv, Git y un agente de IA soportado.

Inicializar proyecto

# Nuevo proyecto con GitHub Copilot
specify init mi-proyecto --integration copilot

# Proyecto actual con Agent Skills para Codex
specify init . --integration codex \
  --integration-options="--skills"

# Descubrir integraciones de esta instalación
specify integration list
🔧 specify init configura plantillas, contexto y comandos o Agent Skills para la integración.

La parte práctica: dos modos de instalación. Se recomienda usar uv tool install para instalación permanente.

specify init prepara todo lo que el agente necesita: instrucciones, plantillas, estructura de carpetas. Después de eso, el agente ya tiene el contexto mínimo para comenzar el ciclo.

Usa specify integration list para ver lo que la versión instalada realmente admite; las opciones no son universales.

Fuentes oficiales consultadas el 2026-07-15: Core Commands e Integrations. Caveat: sustituye vX.Y.Z por una etiqueta real y confirma las opciones en tu versión.

02 / spec-kit — Slash Commands

Slash Commands de spec-kit

⚡ Comandos esenciales (core)

ComandoFuncion
/speckit.constitutionCrea los principios y lineamientos del proyecto
/speckit.specifyDefine que construir (requisitos + historias de usuario)
/speckit.planCrea plan.md con arquitectura y decisiones técnicas
/speckit.tasksCrea una lista de tareas accionables
/speckit.implementEjecuta todas las tareas y construye el proyecto

🔍 Calidad y Feedback

ComandoFuncion
/speckit.clarifyAclara areas subespecificadas (antes del plan)
/speckit.analyzeAnalisis de consistencia entre artefactos
/speckit.checklistGenera checklists de calidad personalizados
/speckit.convergeComprueba completitud y añade gaps a tasks.md
🎯 Funcionan en el contexto del agente: tras specify init, estos comandos quedan disponibles directamente en GitHub Copilot Chat, Claude Code, Cursor, etc.
Nota: en algunos entornos los slash commands pueden no aparecer; alternativa: ejecutar por CLI y/o usar plantillas manualmente.

Ejemplo — Copilot + spec-kit

/speckit.constitution
  Enfocar en calidad de codigo,
  estandares de pruebas y consistencia
  de UX.

/speckit.specify
  API REST de tareas con auth
  JWT y PostgreSQL.

/speckit.plan
  Stack: Node.js + TypeScript +
  Prisma.

Los slash commands son la interfaz operacional de spec-kit dentro del agente. La secuencia lógica es: constitution → specify → plan → tasks → implement.

En la práctica, no todos los entornos de agente soportan slash commands. La alternativa es usar la CLI y las plantillas manualmente — el resultado es el mismo, el flujo es equivalente.

Flecha 1 — Comandos esenciales (core): constitution, specify, plan, tasks, implement. Flecha 2 — Comandos opcionales: clarify, analyze, checklist. Cierre: el comando solo funciona bien si el contexto (PRD, constitution) viene antes.

Después de implementar, /speckit.converge comprueba la completitud y añade el trabajo restante a tasks.md; si quedan gaps, el ciclo vuelve a la implementación.

Fuentes oficiales consultadas el 2026-07-15: README de spec-kit y Evolving Specs. Caveat: la invocación puede usar un slash command o una Agent Skill según la integración.

02 / spec-kit — Flujo SDD

Flujo SDD con spec-kit

Init specify init
Constitucion /speckit.constitution
Especificacion /speckit.specify
Planificacion /speckit.plan
Tareas /speckit.tasks
Implementar /speckit.implement
Converger /speckit.converge
↩ gaps → implementar
📌 Feedback loop: usa /speckit.analyze antes de implementar; después, /speckit.converge añade gaps a tasks.md y el ciclo se repite con revisión humana.

El flujo mantiene vivos los artefactos: constitución, spec, plan y tareas guían la implementación, y la implementación vuelve a compararse con ellos.

/speckit.analyze es un control de calidad recomendado entre tareas e implementación. /speckit.converge comprueba completitud y añade gaps a tasks.md; si queda trabajo, repetimos implement → converge.

Los iconos de persona no son decorativos: los cambios de artefactos y los nuevos lotes de tareas requieren revisión antes de continuar.

Fuente oficial consultada el 2026-07-15: Evolving Specs. Caveat: converge cierra gaps; no sustituye la aprobación humana ni garantiza calidad por sí solo.

02 / spec-kit — Artefactos

Artefactos Canónicos

La intención humana se convierte en una cadena trazable: la spec define qué y por qué; el plan registra arquitectura y decisiones técnicas; las tasks organizan la ejecución.

.specify/memory/constitution.md
specs/<feature>/
├── spec.md    # qué / por qué
├── plan.md    # arquitectura / tech
└── tasks.md   # ejecución trazable
📋 Un PRD.md existente puede ser entrada o referencia; no es un output canónico obligatorio de /speckit.plan.
ComandoArtefacto / intención
constitutionprincipios y gobernanza
specifyspec.md: qué / por qué
planplan.md: arquitectura y decisiones técnicas
taskstasks.md: ejecución trazable
implementcambios en el código
convergegaps añadidos a tasks.md

Este slide corrige una distinción importante: /speckit.plan crea el plan técnico, no un PRD canónico.

Un PRD existente puede enriquecer la entrada, pero los artefactos operativos son la constitución, spec.md, plan.md y tasks.md, seguidos por el código y la convergencia.

Fuentes oficiales consultadas el 2026-07-15: README de spec-kit y spec-driven.md. Caveat: extensiones y presets pueden añadir artefactos sin cambiar el papel de los artefactos core.

02 / spec-kit — Agent Skills

Agent Skills + SKILL.md

Paquete portátil

Cada skill vive en su propio directorio, con instrucciones en el archivo de entrada obligatorio SKILL.md.

Instalación

Las integraciones compatibles aceptan --integration-options="--skills" para generar Agent Skills.

Invocación

El nombre y la sintaxis varían según el agente; la skill conserva la intención del comando spec-kit.

speckit-plan/ → SKILL.md + recursos opcionales. Consulta la integración para conocer ruta e invocación.

Agent Skills empaquetan instrucciones reutilizables en directorios cuyo punto de entrada es SKILL.md. Spec-kit puede generar este formato para integraciones compatibles.

La invocación no es universal: algunas superficies usan slash commands y otras nombres de skill. El contrato duradero es el directorio de la skill y su SKILL.md.

Fuentes oficiales consultadas el 2026-07-15: README de spec-kit e Integrations. Caveat: soporte, directorios y sintaxis dependen de la integración y la versión instalada.
