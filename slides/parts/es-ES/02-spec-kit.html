spec-kit — El Toolkit de SDD

El spec-kit es un toolkit open source mantenido por GitHub que permite enfocarse en escenarios de producto y resultados predecibles, en lugar de hacer "vibe coding" en cada parte desde cero. Operacionaliza SDD con un CLI y slash commands para agentes de IA.

  • Open Source — MIT License · github/spec-kit
  • +70k estrellas no GitHub · 79 contribuidores
  • Mantenido por GitHub, inspirado en la investigacion de John Lam
  • Specify CLI — instalable via uv tool install
  • Slash Commands via integracion del agente (/speckit.*, cuando este soportado)

Mision

"Build high-quality software faster. Focus on product scenarios and predictable outcomes — not vibe coding."

💡 spec-kit ≠ vibe coding. Cada linea de codigo se rastrea hasta un requisito aprobado por una persona.
🤖 Compatible con: GitHub Copilot, Claude Code, Cursor, Gemini CLI, Windsurf, Codex CLI y +20 agentes!

02 / spec-kit - Instalacion

Instalando spec-kit

Opcion 1 - Instalacion permanente (recomendada)

# Instala una vez, usalo en cualquier proyecto
uv tool install specify-cli \
  --from git+https://github.com/github/spec-kit.git

# Verifica herramientas disponibles
specify check

Opcion 2 - Uso unico (sin instalar)

uvx --from git+https://github.com/github/spec-kit.git \
  specify init <PROJECT_NAME>
📋 Prerequisitos: Python 3.11+, uv, Git y un agente de IA soportado.

Inicializar proyecto

# Nuevo proyecto con GitHub Copilot
specify init mi-proyecto --ai copilot

# En proyecto existente
specify init --here --ai copilot

# Windows (PowerShell)
specify init mi-proyecto --ai copilot --script ps

# Con AI Skills integradas
specify init mi-proyecto --ai copilot --ai-skills

# Con Claude Code
specify init mi-proyecto --ai claude
🔧 specify init configura plantillas, slash commands (/speckit.*) y estructura de carpetas automaticamente.
02 / spec-kit — Slash Commands

Slash Commands de spec-kit

⚡ Comandos esenciales (core)

ComandoFuncion
/speckit.constitutionCrea los principios y lineamientos del proyecto
/speckit.specifyDefine que construir (requisitos + historias de usuario)
/speckit.planGenera plan tecnico de implementacion (≈ PRD)
/speckit.tasksCrea una lista de tareas accionables
/speckit.implementEjecuta todas las tareas y construye el proyecto

🔍 Comandos opcionales

ComandoFuncion
/speckit.clarifyAclara areas subespecificadas (antes del plan)
/speckit.analyzeAnalisis de consistencia entre artefactos
/speckit.checklistGenera checklists de calidad personalizados
🎯 Funcionan en el contexto del agente: tras specify init, estos comandos quedan disponibles directamente en GitHub Copilot Chat, Claude Code, Cursor, etc.
Nota: en algunos entornos los slash commands pueden no aparecer; alternativa: ejecutar por CLI y/o usar plantillas manualmente.

Ejemplo — Copilot + spec-kit

/speckit.constitution
  Enfocar en calidad de codigo,
  estandares de pruebas y consistencia
  de UX.

/speckit.specify
  API REST de tareas con auth
  JWT y PostgreSQL.

/speckit.plan
  Stack: Node.js + TypeScript +
  Prisma.
02 / spec-kit — Flujo SDD

Flujo SDD con spec-kit

Init specify init
Constitucion /constitution
Especificacion /specify
Planificacion /plan
✅ Aprobacion puerta humana
↩ rechazado → /plan
Tareas /tasks
Implementar /implement
📌 Human-in-the-Loop: cada artefacto generado por spec-kit se revisa antes de avanzar. La IA ejecuta; el humano valida, corrige y aprueba.
02 / spec-kit — PRD.md

PRD.md — Punto de partida

Tu defines el proyecto y creas el PRD.md con un prompt. Luego usas un prompt junto con /speckit.specify para que el agente lea ese archivo e inicie el ciclo: specify → plan → tasks → implement.

# PRD: [Nombre del Proyecto]

## 1. Vision General
Descripcion concisa del producto y objetivos.

## 2. Requisitos funcionales
- **RF01**: El sistema debe...
- **RF02**: El sistema debe...

## 3. Requisitos No Funcionales
Rendimiento, seguridad, accesibilidad.

## 4. Criterios de Aceptacion
- **CA01**: Comprobable y verificable...

## 5. Preguntas abiertas
- Ambiguedades por resolver...
Por que importa PRD.md para la IA?
  • Usa IDs unicos RF01, CA01 para trazabilidad
  • Criterios de aceptacion comprobables y objetivos
  • Versionado en Git — historial de decisiones
  • Leido por humanos y maquinas
Sin PRD.mdCon PRD.md
Contexto vago y efimeroContexto estructurado y persistente
Alucinaciones frecuentesAlucinaciones drasticamente reducidas
Trazabilidad imposibleAutomatica via IDs (RF, CA)
Onboarding lentoRapido con PRD.md + AGENTS.md
02 / spec-kit — Checklist Operacional

Mini Checklist de Calidad (Spec → Plan → Tasks)

Spec

  • Objetivos + no objetivos explicitos
  • Criterios de aceptacion comprobables
  • Ejemplos y casos borde relevantes

Plan

  • Descomposicion incremental por etapas
  • Dependencias y riesgos mapeados
  • Puerta de revision humana antes de implementar

Tasks

  • Small batches (cambios pequenos)
  • Verificacion en cada lote (test/lint/build)
  • Evidencia de finalizacion por tarea
✅ Si el checklist pasa, el agente gana velocidad sin perder confiabilidad.
