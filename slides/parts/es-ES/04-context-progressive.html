04 / Context Engineering

El Contexto es una Decisión de Arquitectura

Intención

Spec, resultado, alcance y criterios definen la decisión actual.

Restricciones

Instrucciones, seguridad, arquitectura y límites reducen ambigüedad.

Evidencia

Código, pruebas, decisiones y fuentes de verdad sostienen la respuesta.

El mismo modelo + la misma tarea pueden producir resultados distintos cuando cambia el contexto seleccionado.

04 / Progressive Disclosure

Progressive Disclosure

Progressive Disclosure es el principio de revelar solo el contexto necesario para la tarea actual. En SDD, esto significa dividir el conocimiento del agente en capas — cargando información especializada bajo demanda, ahorrando tokens, reduciendo ruido y disminuyendo retrabajo.

  • AGENTS.md raíz: mínimo, global y estable — reglas válidas para todas las tareas
  • Skills especializadas: cargadas bajo demanda, solo cuando son necesarias
  • Context Window: hasta 70% de ahorro en el flujo medido por la autora
  • Calidad: menos ruido produce respuestas más precisas y consistentes

Analogía

Como un médico especialista: el médico general atiende lo básico; el especialista es llamado solo cuando el problema lo exige. El contexto funciona igual — carga al especialista solo cuando sea necesario.

AGENTS.md minimalista + Skills bajo demanda reduce el contexto persistente sin perder profundidad.

Fuentes: Agent Skills Specification · estudio de la autora

Progressive Disclosure trata de foco: cargar solo el contexto necesario para la tarea actual. La estrategia práctica es una base global mínima más especialización bajo demanda.

Esto reduce ruido, mejora la precisión de la respuesta y reduce el costo de tokens por sesión. Menos ruido significa menos inferencia necesaria por parte del modelo.

El “hasta 70%” proviene del flujo de trabajo de la autora documentado en LinkedIn; no es una promesa universal. Cada equipo debe medir su propio resultado.

Cierre: menos ruido produce respuestas más consistentes y previsibles.

Aislamiento de contexto

Subagents

Delega subproblemas bien delimitados sin contaminar el contexto de la tarea principal.

Ahora el foco cambia de cargar conocimiento a aislar trabajo.

Un subagent recibe una pregunta delimitada y devuelve resultado compacto, evidencia e incertidumbres a la tarea principal.

04 / Subagents

Aísla el Subproblema

Delegar

Una pregunta delimitada, con entradas y criterio de retorno explícitos.

Aislar

Un contexto de trabajo separado evita contaminar la tarea principal.

Retornar

Un resultado compacto con evidencia, incertidumbre y riesgos restantes.

Subagent es un trabajador aislado; Skill es conocimiento reutilizable; un comando nativo pertenece a una superficie.

Los subagents ayudan cuando el subproblema puede aislarse y el retorno cabe en un resumen verificable.

No trates subagent, Agent Skill y comando de producto como sinónimos; resuelven responsabilidades diferentes.

Continuidad entre ejecuciones

State &
Memory

Preserva decisiones y evidencias útiles sin cargar el transcript completo.

Después de aislar trabajo, debemos decidir qué sobrevive entre ejecuciones.

State mantiene la situación actual; memory preserva conocimiento duradero y curado sin convertir todo el historial en contexto permanente.

04 / State & Memory

Preserva Decisiones, No el Transcript Completo

State actual

Objetivo, restricciones, progreso y próxima decisión.

Memory curada

Hechos y decisiones duraderas, con origen y vigencia.

Evidencia

Los éxitos repetitivos pueden resumirse; los fallos conservan detalles.

compaction ≠ clearing ≠ editing ≠ isolation ≠ caching

Memory no es el transcript completo. Lo que sobrevive debe apoyar decisiones futuras sin cargar toda la conversación.

Compaction resume, clearing reinicia, editing modifica, isolation separa y caching reutiliza procesamiento; son mecanismos distintos.

04 / Transición a Economía

Del Contexto Correcto al Contexto Sostenible

1 · Curaduría

Context Engineering decide qué fuentes pueden cambiar la decisión actual.

2 · Límites

Context Economy limita contexto, coste, tiempo, intentos y tamaño del diff.

3 · Salida

Las señales de degradación indican cuándo concluir, compactar, aislar o hacer handoff.

En una frase: Context Engineering elige lo que merece entrar; Context Economy define cuánto cabe, durante cuánto tiempo y qué señal cierra el ciclo.

“Bridge” era solo una transición editorial entre dos preguntas. La diapositiva ahora explica esa transición directamente.

Primero curamos la información. Después añadimos límites operativos y criterios de salida para mantener la sesión verificable.
