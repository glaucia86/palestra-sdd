04 / Arquitectura - AGENTS.md

AGENTS.md — El Contrato Vivo

AGENTS.md es un estandar abierto para comunicar a los agentes de IA el contexto, las reglas y los comportamientos esperados de un repositorio. Ubicado en la raiz del proyecto, lo leen varias herramientas y agentes (segun el producto/integracion), actuando como un "README para agentes".

Ubicacion

Siempre en la raiz del repositorio — ./AGENTS.md

Documento Vivo

Actualizado junto al proyecto, siempre refleja el estado actual.

# AGENTS.md

## Objetivo del Proyecto
API REST de gestion de tareas.

## Stack Tecnologico
- Node.js 22 + TypeScript strict
- Express 5 + Prisma ORM
- PostgreSQL 16
- Vitest para pruebas

## Convenciones de Codigo
- Nomenclatura: camelCase para variables
- Imports: siempre absolutos (src/...)
- Errores: nunca uses `any`, usa Result types

## DO ✅
- Escribe pruebas para cada funcion publica
- Use TypeScript strict mode
- Documenta endpoints con JSDoc

## DON'T ❌
- No uses `any` type
- No hagas commit sin pruebas pasando
- No alteres el schema sin migracion
AGENTS.md es el "contrato vivo" del proyecto con los agentes de IA. Define el contexto del proyecto, las reglas de comportamiento y dónde encontrar información especializada. Lo importante: es un estándar abierto, no propietario de GitHub. El ejemplo muestra el patrón "README for agents": stack tech, convenciones de código, DO/DON'T explícitos. Cuanto más específico, menor la tasa de alucinación.
04 / Arquitectura - Rules

Rules — Lineamientos Globales

Rules son lineamientos globales que definen el comportamiento por defecto del agente para todo el workspace, sin depender del proyecto o de la tarea.

📌 Cada agente expone Rules de forma diferente: Copilot usa .github/copilot-instructions.md; Codex prioriza AGENTS.md; otros agentes pueden usar archivos propios.
Las Rules son el "modo por defecto" del agente. AGENTS.md puede sobrescribir Rules para un proyecto especifico.

DO — Siempre hacer

  • Use TypeScript strict mode
  • Escribe pruebas para funciones publicas
  • Documenta APIs con OpenAPI/JSDoc
  • Sigue principios SOLID y Clean Code
  • Valida entradas en cada frontera externa

DON'T — Nunca hacer

  • Usar any type en TypeScript
  • Hacer commit sin pruebas pasando
  • Hardcodear credenciales o secretos
  • Ignorar errores silenciosamente (empty catch)
Las Rules son el nivel más transversal del contexto: aplican a todos los proyectos del workspace, no a uno específico. En Copilot, .github/copilot-instructions.md es el archivo principal de Rules. DO/DON'T estructura importante: reglas en positivo ("usa TypeScript strict") son más efectivas que reglas solo en negativo. El "never" se reserva para restricciones de seguridad.
04 / Arquitectura - Skills.md

Skills.md — Conocimiento Especializado

Skills son directorios con un archivo SKILL.md como entrada — patron abierto de agentskills.io adoptado por GitHub Copilot en dic/2025. El agente mantiene la descripcion en contexto y carga el contenido completo solo cuando es necesario: Progressive Disclosure en la practica.

Performance

Menos tokens consumidos = sesiones mas eficientes y baratas.

Portabilidad

Las Skills funcionan en Codex, Claude Code, Cursor, Gemini CLI y otras herramientas compatibles.

📖 Ver seccion 05 para profundizar en Progressive Disclosure — principios, estructura en capas y buenas practicas.
Ejemplos reales (clicables):
find-skills · vercel-react-best-practices · web-design-guidelines · frontend-design
🎯 Carga solo la Skill de la tarea actual para reducir ruido y tokens en el contexto.
Las Skills son el mecanismo de Progressive Disclosure aplicado al conocimiento especializado. En lugar de cargar todo el contexto de arquitectura React en cada prompt, se carga solo cuando la tarea lo requiere. Skills.io / agentskills.io es el registro público de habilidades reutilizables — mismos principios que npm para dependencias de código, pero para conocimiento de agentes.

05 / Economía de Contexto

El contexto ahora tiene costo

Usage-based billing cambia la conversación. El contexto ya no es solo calidad: también es costo, latencia y gobernanza.
  • Input tokens
    Todo lo que el modelo recibe: prompts, specs, archivos e instrucciones.
  • Output tokens
    Todo lo que el modelo devuelve: planes, código, explicaciones y diffs.
  • Cached tokens
    Contexto reutilizado con pricing propio, según la documentación oficial.

GitHub AI Credits

A partir del 01/06/2026, las interacciones de Copilot migran hacia billing por consumo. La documentación define 1 GitHub AI Credit = US$0.01.

No copies tablas de precios en slides: modelos, multiplicadores y allowances cambian. Enlaza la fuente oficial y revisa antes de presentar.
05 / Economía de Contexto — Prácticas

Economía de tokens: qué funciona

Contexto bajo demanda

PRD, AGENTS.md y Skills cargan la información correcta cuando la tarea la necesita.

Cache y prefijos estables

Instrucciones estables al inicio del contexto aumentan la posibilidad de reaprovechar prompt caching.

Modelo correcto

No toda tarea necesita el modelo más caro: clasifica riesgo, complejidad y necesidad de razonamiento.

Salida corta

La concisión reduce output tokens. Caveman es un ejemplo útil, pero no elimina costo de reasoning y herramientas.

Batch y flex

Tareas asíncronas pueden usar procesamiento más económico cuando la latencia no es crítica.

Observabilidad

Mide input, output, cached tokens, modelo usado, retrabajo y costo por ejecución.

Regla práctica: ahorrar tokens no es solo escribir menos. Es reducir ambigüedad, repetición, loops largos y contexto irrelevante.
05 / Economía de Contexto — SDD

SDD como FinOps de agentes

Spec clara reduce desperdicio

  • Menos prompts repetidos para explicar la misma intención.
  • Menos iteraciones largas para corregir requisitos implícitos.
  • Menos tool calls exploratorias porque el criterio ya está definido.

Anti-patterns caros

  • Prompt gigante copiado en toda sesión.
  • Logs completos y outputs de herramientas sin filtrar.
  • Modelo caro para triage simple o tarea mecánica.
SDD no es solo calidad de entrega. En agentes, una buena spec también controla costo, latencia, riesgo y previsibilidad.
05 / Progressive Disclosure

Progressive Disclosure

Progressive Disclosure es el principio de revelar solo el contexto necesario para la tarea actual. En SDD, eso significa dividir el conocimiento del agente en capas — cargando informacion especializada bajo demanda, ahorrando tokens y reduciendo ruido.

  • AGENTS.md raiz: minimo, global y estable — reglas validas para todas las tareas
  • Skills especializadas: cargadas bajo demanda, solo cuando hace falta
  • Context Window: hasta 70% de ahorro de tokens (ref. LinkedIn — Glaucia Lemos)
  • Calidad: menos ruido = respuestas mas precisas y consistentes

Analogia

Como en medicina: el medico general atiende lo basico; el especialista se llama solo cuando el problema lo exige. El contexto funciona igual.

📊 AGENTS.md minimalista + Skills bajo demanda puede reducir hasta 70% el uso de context window por sesion. (ref. LinkedIn — Glaucia Lemos)

↓ presiona ↓ para continuar en esta seccion

El 70% de reducción en tokens no es un número mágico — es la consecuencia lógica de cargar solo lo que se necesita. Un AGENTS.md de 50 líneas más Skills especializadas es más eficiente que un AGENTS.md monolítico de 500 líneas. La analogía médica funciona en presentaciones: el médico general / especialista ayuda a audiencias no técnicas a entender la jerarquía de contexto inmediatamente.

AGENTS.md — Ejemplo Minimalista

# AGENTS.md

## Proyecto
API de gestion de tareas con JWT.

## Reglas Globales
- TypeScript strict mode
- Pruebas obligatorias para funciones publicas
- Nunca uses `any` type

## Instrucciones Especializadas
- Pruebas: docs/agents/testing.md
- Arquitectura: docs/agents/architecture.md
- Seguridad: docs/agents/security.md

## Limites del Agente
- No alteres el schema sin migracion
- No hagas commit sin pruebas pasando
💡 La IA genera archivos especializados automaticamente - no necesitas crearlos manualmente.
La estructura de carpetas en este ejemplo es el "spec-kit" estándar que recomendamos. docs/agents/ para instrucciones especializadas, .github/copilot-instructions.md para Rules globales, skills/ para habilidades. El comentario "💡 La IA genera archivos especializados automáticamente" es importante: esto no es trabajo manual adicional — es parte del flujo SDD donde el primer prompt genera la arquitectura completa.
05 / Progressive Disclosure — Principios

6 Principios de Progressive Disclosure

1. Minimalismo

AGENTS.md debe contener solo reglas necesarias para todas las tareas del repositorio. Reglas especificas van en archivos secundarios.

2. Separacion

Instruccion especializada → archivo secundario (docs/agents/). Nada de "documento gigante" con todo adentro.

3. Delegacion

AGENTS.md raiz declara donde encontrar instrucciones especializadas mediante enlaces. El agente las busca cuando hace falta.

4. Accionabilidad

Prefiere instrucciones directas: "Antes de cambiar codigo, explica el motivo." Evita textos genericos como "sigue buenas practicas".

5. Estabilidad

Las estructuras de carpetas inestables y la informacion volatil no deben ir en AGENTS.md raiz; deben quedar en archivos secundarios.

6. Economia

Cada token ahorrado = respuestas mas rapidas y baratas. Un AGENTS.md ligero mejora la calidad y reduce el costo por sesion.

📚 Estos archivos especializados tambien se conocen como "Skills" en la comunidad de agentes de IA (Claude Code, Cursor, etc.) — mismo concepto, carga bajo demanda.
Los 6 principios son el marco prescriptivo para implementar Progressive Disclosure correctamente. Son accionables: después de esta diapositiva, el equipo puede auditar su AGENTS.md actual contra cada principio. Punto de enganche para la audiencia: ¿cuántos de estos principios viola el AGENTS.md (o copilot-instructions.md) que tienen hoy? Los más comunes: falta de separación y exceso de información volátil en el archivo raíz.
